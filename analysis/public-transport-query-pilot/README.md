# 臺中公車官方網站旅運規劃試測

試測日期：2026-08-25  
來源：[台中公車即時動態資訊－旅運規劃](https://citybus.taichung.gov.tw/ebus)  
目的：確認以官方網站的標準化起訖查詢，能否形成商圈「公共運輸可達性」的可重複觀測資料。

## 結論

**功能試測通過，但只能作為標準化 OD 查詢型的可達性代理指標，不能用單次查詢代表整個商圈的公共運輸可達性。**

官方網站可回傳查詢時間、起訖站、總旅行時間、出發／抵達時間、公車路線、轉乘、步行銜接、經過站數及距離。這些欄位足以建立「由固定交通節點前往商圈代表站點」的可達性測量；後續必須固定起點、商圈代表站、平／假日與時段，才可公平比較四個商圈。

## 發現的資料與介面風險

- 網站頁尾明示適用 Chrome、Edge；本次內建瀏覽器無法正常展開旅運規劃，Chrome 可正常操作。
- 起訖點必須從自動完成清單選取，只有輸入文字不會形成有效查詢。
- 同名站點可能有不同方向或地址；研究必須保存站名與地址，不可只存「臺中車站」或「逢甲大學」。
- 方案 15 顯示 06:04–06:39，早於 09:48 的指定時間，判定為時間異常，正式計算時應排除並保留異常旗標。
- 官網明示規劃結果僅供參考，實際搭乘仍以業者發車班表為準。
- 查詢結果會隨日期、時段與班表更新而改變；每筆資料須保存查詢日期、指定出發時間、擷取時間與原始畫面或結果快照。

## 建議的競賽版測量設計

將公共運輸定位為 TCDPI 以外的「結構驅動指標」。每個商圈使用相同設計：

- 固定 3 個外部起點，例如臺中車站、高鐵臺中站及市政府。
- 固定 1 個商圈代表站；若商圈範圍較大，可事前凍結 2 個代表站並取較佳值或平均值。
- 分平日、假日；每類選 12:00、18:00、21:00 三個時段。
- 原始設計共 `3 起點 × 4 商圈 × 2 日型 × 3 時段 = 72` 筆 OD 查詢。

每筆查詢優先保存：

1. 最短有效旅行時間。
2. 最早抵達等待時間。
3. 60 分鐘內有效方案數。
4. 是否存在免轉乘方案。
5. 最少轉乘次數。
6. 步行距離；步行時間缺漏時不強行估補。

正式比較前須先寫定異常排除規則，例如出發時間早於指定時間、抵達時間倒置、缺少路線或總時間。網站查詢資料適合競賽雛形與外部解釋分析；若要投稿期刊，應再以正式 API／TDX 或保存的原始查詢回應提升規模、稽核性與重現性。
